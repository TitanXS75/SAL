## 1. Existing Codebase Analysis

The parent project (`Website-downloader`) is a **website asset downloader** built on:
- **Express.js** + **Handlebars (HBS)** templates
- **Socket.io** for real-time progress streaming
- **wget.exe** (bundled binary) for recursive site mirroring
- **archiver** for zipping downloaded assets

### What exists vs. what we need

| Existing (Parent) | Required (Assignment) |
|---|---|
| Download raw HTML/CSS/JS files via wget | AI-analyze a website's UI structure |
| Zip and serve the downloaded bundle | Generate a clean React/Next.js clone |
| Real-time scan/download progress via Socket.io | Natural-language modification of generated code |
| No AI integration | Full LLM-powered analysis + code generation pipeline |
| Output: offline copy of original site | Output: fresh React codebase that *reimplements* the UI |

**Key insight:** The parent project downloads websites as-is. This assignment requires *understanding* and *recreating* the frontend as a new React codebase using AI, not copying raw files.

## 3. Technology Stack

### Backend (Orchestration & API)
- **Node.js** + **Express** — API server
- **Socket.io** — Real-time streaming of agent progress to UI
- **Puppeteer** — Headless Chrome for full JS-rendered page scraping
- **sharp** — Screenshot processing
- **Google Gemini 1.5 Flash / Pro** — Primary LLM (cost-efficient, vision capable)
  - Vision for screenshot analysis
  - Text for code generation & modification
- **Axios** — HTTP client for scraping raw HTML/CSS
- **fs-extra** — File system operations for generated projects

### Frontend (Agent Control UI)
- **Vanilla HTML/CSS/JS** with Socket.io client (same pattern as parent)
- Real-time log streaming, URL input, chat modification panel

### Generated Output
- **Next.js 14** (App Router) + **TypeScript**
- **Tailwind CSS** — for generated sites (quick, responsive, reliable)
- Components auto-generated by AI

### Development Tools
- **concurrently** — Run backend + generated Next.js preview in parallel
- **dotenv** — API key management

## 4. Analysis Pipeline (Step-by-Step)

### Step 1: Scrape (Multi-modal data collection)
```
URL → Puppeteer → {
  screenshot (full-page PNG),
  html (full DOM),
  css (all stylesheets),
  metadata: {
    title, description, fonts,
    colors (computed styles),
    sections (h1-h6 headings, nav, main, footer),
    images (src list),
    links (nav links)
  }
}
```

### Step 2: AI Analysis
Send to Gemini Vision:
- Full-page screenshot
- Extracted HTML structure (trimmed)
- Color/font metadata

Receive structured JSON:
```json
{
  "layout": "hero + features + testimonials + footer",
  "colorPalette": ["#1a1a2e", "#e94560", "#ffffff"],
  "typography": { "heading": "Inter", "body": "Roboto" },
  "sections": [
    { "type": "navbar", "content": [...] },
    { "type": "hero", "content": {...} },
    ...
  ],
  "components": ["Button", "Card", "TestimonialCard"],
  "responsive": true
}
```

### Step 3: Code Generation
Feed structured analysis → Gemini Pro:
- Generate individual React components
- Generate pages/layout
- Generate Tailwind config with extracted color palette
- Generate `next.config.js`, `package.json`

### Step 4: Validation & Error Handling
```
npm install → npm run build
     ↓ errors?
Gemini error-fix loop (max 3 retries):
  - Parse build error
  - Send error + code to LLM
  - Apply fix
  - Rebuild
```

### Step 5: Preview
- Spin up `npm run dev` on the generated Next.js project
- Open browser or provide URL in UI

### Step 6: Modification (Natural Language)
- User types: "Make navbar sticky"
- Backend: identify relevant files, send to Gemini with instruction
- Apply diff, rebuild, hot reload

## 7. Key Implementation Decisions

### Why Gemini over ChatGPT/Claude for primary LLM?
- **Multimodal**: Gemini 1.5 Flash accepts screenshot + text in one API call
- **Cost**: Flash model is significantly cheaper than GPT-4V
- **Context window**: 1M tokens — can fit entire page HTML

### Why Puppeteer over simple HTTP fetch?
- JavaScript-rendered sites (React/Next.js/Vue) require actual browser execution
- Full-page screenshots enable vision-based analysis
- Can extract computed CSS (actual rendered colors/fonts)

### Why Next.js for generated output?
- Assignment explicitly prefers React/Next.js
- App Router + TypeScript is modern standard
- Tailwind CSS works perfectly for AI-generated responsive layouts

### Why Tailwind for generated sites?
- LLMs are trained on enormous amounts of Tailwind code
- More reliable code generation than vanilla CSS
- Auto-responsive with breakpoints

### Error Handling Strategy
- Parse TypeScript/Next.js build errors
- Send error message + file contents to LLM
- Ask LLM to produce a minimal targeted fix
- Max 3 retries to avoid infinite loops

### Cost Awareness
- Use Gemini Flash (not Pro) for first analysis pass
- Cache scraped content — don't re-scrape for modifications
- Only send changed files to LLM during modifications
- Limit screenshot resolution to 1280x800

## 8. Limitations (Honest Assessment)

- **Complex SPAs**: Highly dynamic apps (dashboards, maps) harder to recreate
- **Proprietary fonts**: Fonts behind paywalls won't be accessible
- **Animations**: Complex CSS animations may be simplified
- **Authentication-gated content**: Agent can't scrape pages behind login
- **Pixel-perfect accuracy**: LLM-generated code won't be identical to original
- **Build errors**: Some edge cases may exceed the 3-retry fix limit
